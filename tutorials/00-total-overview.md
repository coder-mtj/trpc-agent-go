## 2. 先解决几个"看不懂的词"

在读下去之前，先把这几个词用大白话讲清楚。后面所有文章都会用到它们。

### 2.1 什么是"大语言模型（LLM）"？

就是像 ChatGPT、DeepSeek、通义千问、豆包这类东西的"大脑"。

大白话：**一个读过海量文字、学会了接话的超级"接话员"**。你给它一句话，它根据学过的知识，一个字一个字地"猜"出最合理的下一句话，就这样生成一整段回答。

它本身只会"说话"，不会"动手"。比如你问它"帮我算一下 2+3"，它能回答"等于 5"，但如果要它真的去操作电脑、查数据库，它做不到——除非给它工具。

### 2.2 什么是"AI 智能体（Agent）"？

英文 Agent 直译是"代理"，但在 AI 领域里，我们把它理解成：**一个会思考、会做计划、会调用工具、最后把事情办成的 AI 角色**。

大白话：普通聊天机器人像"只会聊天的客服"，你说一句它答一句；而智能体更像"一个能自己安排工作的员工"——它收到任务后，可以自己决定"先查资料，再写代码，再测试，最后交报告"。

### 2.3 什么是"框架（Framework）"？

框架就是**别人已经搭好的半成品骨架**，你在上面填自己的内容就行。

类比：建房子，框架是已经浇好的承重墙和房顶，你只需要装修、买家具，不用自己从挖地基开始。写程序也一样——框架把麻烦的、重复的部分（比如怎么跟 AI 对话、怎么保存聊天记录、怎么调用工具）都做好了，你只需要告诉它"我要做哪个智能体、用哪个模型、给哪些工具"。

### 2.4 什么是"工具（Tool）"？

工具就是**智能体能主动使用的"手和脚"**。

比如：计算器工具、搜索工具、执行代码的工具、发邮件的工具。模型只会说话，工具负责动手，两者配合才能"既会想又会做"。

### 2.5 什么是"RPC"和"tRPC"？

- RPC（Remote Procedure Call）：让一个程序能像打电话一样，调用另一台电脑上的程序功能。
- tRPC：腾讯开源的一套 RPC 框架，相当于电话线标准。

这个项目叫 tRPC-Agent-Go，意思是"**跟 tRPC 同一家族的、专门做 AI 智能体的 Go 版本**"。不过你不需要懂 RPC 的细节，本教程不依赖它。

## 3. 这个框架能干什么？

官方 README 列了几个典型场景，我用大白话翻译一下：

| 场景 | 大白话解释 |
|------|-----------|
| 客服机器人 | 能理解上下文、多轮对话、自己查订单/知识库来解答问题 |
| 数据分析助手 | 帮你查数据库、算数据、生成图表和报告 |
| DevOps 自动化 | 自动部署、监控、处理故障，相当于一个会动手的运维 |
| 业务流程自动化 | 把多步骤的业务流程串起来，需要人确认的地方停下来等人确认 |
| 知识问答（RAG） | 给它一堆公司文档，它能"读"完文档后回答文档里才有答案的问题 |

它最重要的几个能力（后面每篇都会展开）：

1. **多智能体协作**：好几个 AI 角色分工合作（比如一个负责分析、一个负责写报告），可以串行、并行、循环。
2. **工具调用**：给智能体接上任意工具，让它自己决定什么时候用。
3. **会话和记忆**：记住你跟它聊过什么，多轮对话不断片；还能保存长期记忆。
4. **知识检索（RAG）**：给模型配一个"外接硬盘"，回答时先查资料再回答。
5. **自我进化**：回顾历史对话，把好的做法提炼成可复用的"技能说明书（SKILL.md）"。
6. **评估与测试**：有专门的评测系统，能量化地检验智能体做得好不好。
7. **可观测性**：每一步做了什么、花了多长时间、调用了哪个模型，都有记录可查（OpenTelemetry）。

## 4. 一个最简单的智能体长什么样？

用这个框架写一个带计算器工具的智能体，核心代码只有这么几行（不用看懂，先感受一下）：

```go
// 概念版伪代码：用 Go 语法演示逻辑，真实项目就是 Go 实现

// 1. 选一个"大脑"（模型）
modelInstance, err := openai.New("deepseek-chat") // 对应源码 openai.New(...)

// 2. 给一个"工具"（计算器）
calculatorTool, err := function.NewFunctionTool(calculator) // 对应源码 function.NewFunctionTool(...)

// 3. 把大脑和工具装进一个"智能体"
agent, err := llmagent.New(
    "assistant",
    llmagent.WithModel(modelInstance),   // 对应 WithModel(...)
    llmagent.WithTools(calculatorTool),  // 对应 WithTools(...)
)

// 4. 创建一个"调度器"（Runner）来跑对话
runner, err := runner.NewRunner("calculator-app", agent)

// 5. 用户说一句话，框架返回一串"事件"
//    对应源码 runner.Run(ctx, "user-001", "session-001", ...)
events, err := runner.Run(ctx, "user-001", "session-001", event.NewUserMessage("Calculate what 2+3 equals"))
```

这就是全部！框架把"怎么跟模型对话、怎么把聊天记录存下来、怎么让模型调用工具、怎么把结果推给前端"这些麻烦事都包了。

## 6. 读之前需要知道的事

1. **这是个框架，不是一个能直接打开玩的软件。** 它没有主程序，你要用它写自己的程序。
2. **它是 Go 语言写的。** 如果你不会 Go 也没关系，本教程不要求你会写 Go，只要求你能看懂"大概意思"。
3. **要真正跑起来，需要一个模型的 API Key**（比如 DeepSeek、OpenAI 的）。不过大部分示例支持"假模型（fake model）"模式，不需要花钱也能跑通流程。
4. **它还在快速迭代。** 你本地仓库的 main 分支可能比线上稍旧一点，不影响学习。
